# CodePerms

Серверные права для Minecraft 1.7.10. Группы с наследованием и весами, личные ноды и мета игроков,
треки для повышения и понижения, временные выдачи, контексты (мир, измерение, оператор).

Мод заменяет встроенную реализацию `PermissionService` из CodeCore своей. Владельца роли `permissions`
выбирает ядро по ключу `permissions` секции `[owners]` файла `config/code/config.toml`: `auto` отдаёт
роль CodePerms, если он стоит, `off` оставляет сервер без прав вовсе, а имя владельца (`codeperms`,
`luckperms`) называет его прямо. Роль ушла другому владельцу, и CodePerms отходит целиком: ни команд,
ни своих файлов, только строка в лог о том, кто теперь держит права.

Так же мод отходит, когда имя провайдера хранилища из секции `[storage]` главного файла не занял ни
один мод: отката на встроенное хранилище нет, права остаются на встроенной json-реализации ядра, а в
лог уходит строка с именем шва и именем из конфига.

Файл прав ядра переезжает командой `/perms import`, формат нод совпадает один в один.

Клиентской части нет: ванильный клиент заходит на сервер с CodePerms без этого мода.

## Требования

- Minecraft 1.7.10, запуск на Java 8.
- CodeCore 1.1.0 или новее, зависимость `required-after:codecore`.

## Установка

| Файл | Куда |
|---|---|
| `CodePerms-1.1.0-server.jar` | `mods/` сервера |
| `codeperms-1.1.0-api.jar` | тем, кто пишет свой провайдер прав: компиляция, на сервер не нужен |
| `codeperms-1.1.0-dev.jar` | им же: deobf-версия для dev-запусков |

Клиентской части нет: ванильный клиент заходит на сервер без этого мода. Ставится после CodeCore.
Java 8 или 17 и 21 под lwjgl3ify, Minecraft 1.7.10, Forge 10.13.4.1614.

## Сборка

Нужен JDK 25 (версию демона задаёт `gradle/gradle-daemon-jvm.properties`), wrapper скачает Gradle
сам. Байткод собирается под Java 8 через jabel, поэтому мод грузится на обычной 1.7.10.

```
./gradlew build
```

В `build/libs` появятся универсальный `CodePerms-1.1.0.jar` для dev-запусков и
`CodePerms-1.1.0-server.jar` для сервера. Раздавать универсальный jar игрокам нельзя: в нём
есть серверный код.

## Подключение

1. Собрать и опубликовать зависимости локально: `CodeSides` и `CodeCore` через `publishToMavenLocal`.
2. Здесь: `./gradlew build`.
3. На сервер в `mods` положить `codecore` и `CodePerms-1.1.0-server.jar`.

Права лежат в `config/code/permissions/`: `perms.toml` с настройками, `perms-groups.toml` с группами и
треками, `perms-players.json` с игроками. Рядом там же живёт `core-groups.toml` встроенной реализации
ядра, который переезжает командой `/perms import`. Управление через `/perms`, автодополнение и
подсказки по нодам прав: собственные ноды мода зарегистрированы в каталоге, так что дополнение работает
сразу после установки. Списки групп и треков постраничные, карточки групп и игроков связаны кликами:
строки списков, родители и группы игрока ведут на карточки, ноды открываются второй страницей. Кнопки
правки появляются только у тех, у кого есть нода на них.

Общее для всей линейки лежит в главном файле `config/code/config.toml`: имя провайдера хранилища и
интервал автосохранения в `[storage]`, записи в лог в `[audit]`, группа по умолчанию и группа
операторов в `[permissions]`. В `perms.toml` остаётся редкое: `applyOps`, `defaultNodes`, потолки
`limits`, `expiry.scanTicks`, `cache.offlineCacheSize`. Ни один ключ не встречается в обоих файлах.

Группу, названную в `defaultGroup` или `opGroup` секции `[permissions]` главного файла, мод не
переименовывает и не удаляет: сначала правится настройка, иначе снимок разъехался бы с файлом. Оба имени
приводятся к нижнему регистру, как и идентификаторы групп. Записи, которые не влезли
в потолки из `limits`, остаются в файле нетронутыми и не попадают в модель, о каждой такой пишется
строка в лог. `/perms reload` перечитывает и потолки `limits.*` вместе с остальным содержимым файлов:
перезапуск для них не нужен.
